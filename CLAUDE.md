# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Personal portfolio site for a Data Engineering Manager, built with **Astro** and deployed to GitHub Pages. Content is data-driven (JSON) and internationalized in three languages: pt-BR, en-US, es-ES. Motion uses GSAP + Lenis. (This repo was migrated from Jekyll to Astro; some legacy files under `assets/js/` and several root `*.md` docs predate the migration.)

Live at: https://donotavio.github.io/cv-site-otavio/

## Build & Development Commands

```bash
npm install                                 # Install dependencies
npm run dev                                 # Local dev server (astro dev)
npm run build                               # Build static site into dist/
npm run preview                             # Preview the production build
npm run check                               # Type-check (astro check)
```

### Data Pipeline Scripts (Python 3.11)

```bash
pip install requests beautifulsoup4         # Python dependencies
python3 scripts/fetch_github_data.py        # Update github_activity.json (needs GITHUB_USERNAME, GITHUB_TOKEN)
python3 scripts/fetch_linkedin_data_enhanced.py  # Update LinkedIn JSON (needs LINKEDIN_PROFILE_URL, LINKEDIN_SESSION_COOKIE)
python3 scripts/translate_projects.py       # Regenerate translated project strings
python3 scripts/build_profile_data.py       # Build consolidated profile.json
```

There are no unit tests. Verify changes manually: language switcher, timeline interactions, responsive layout.

Dois checks automatizáveis existem e valem rodar antes de commitar mudança de página/dados:

```bash
python3 scripts/validate_i18n.py            # paridade de chaves pt-BR/en-US/es-ES (exit≠0 se divergir)
npm run build && node scripts/render_check.mjs --page eleicoes-2026   # smoke test de render (precisa: npm i jsdom --no-save)
```

`render_check.mjs` existe porque **build verde ≠ página correta**: as páginas de dashboard montam quase tudo em runtime via `innerHTML` a partir dos JSONs, então uma seção pode ir ao ar vazia, sem estilo ou presa em "carregando…" com `astro check`/`astro build` passando. Ele carrega o HTML buildado + o bundle JS real em jsdom, serve os assets do disco e relata, por seção, se renderizou (`✓`), está aguardando dado (`⏳`), quebrou (`✗`) ou ficou presa no placeholder. Útil sobretudo em ambiente headless sem browser. Limitação conhecida: páginas cujo script principal é módulo ES com `import` (hoje: `brasil-cockpit`) não são executáveis por `window.eval` — o script reporta **INCONCLUSIVO** (exit 3) em vez de um falso OK.

## Architecture

### Astro Layer
- `astro.config.mjs` — Astro config (`base: /cv-site-otavio`, static output → `dist/`)
- `src/layouts/BaseLayout.astro` — Base HTML shell
- `src/pages/index.astro` — Home page, composes the section components in order; sibling pages: `pix-observatory`, `data-stack-radar-br`, `brasil-cockpit`, `eleicoes-2026`
- `src/components/*.astro` — one component per home section (Hero, About, ArchitectureFlow, Impact, AiDelivery, EnrichmentMachine, Timeline, Skills, TechStack, Projects, GitHubStats, Blog, Recommendations, Contact, Navigation, …). Each section header carries a `[ NN ]` mono-label index that is **sequential in DOM order** — inserting a section means renumbering the following ones.
- `src/styles/*.css` — `tokens.css` is the color/type source of truth (**never hardcode hex outside it**); plus `reset`, `global`, `layout`, `fonts`, `transitions`, `print`.
- `src/lib/i18n.ts` — build-time `t(key)` helper (imports `pt-BR.json`); renders default text into the HTML at build (SSG) so content is visible without JS and CLS ~0.
- `src/scripts/motion/` — motion engine on **GSAP + Lenis**. Only 5 named patterns are allowed (`resolve`, `reveal-up`, `hairline-draw`, `hover-glow`, `smooth-scroll`); all gated by `motionOk` (respects `prefers-reduced-motion`). Durations/easings in `constants.ts` — no ad-hoc values.

### Runtime i18n / legacy JS
- `assets/js/i18n.js` — runtime language switch: fetches `/assets/i18n/<lang>.json` and swaps `[data-i18n-key]` / `[data-i18n-aria]` text without reload.
- Other `assets/js/*.js` (`main.js`, `content.js`, `timeline.js`, `animations.js`, …) are **legacy pre-Astro modules**; new work belongs in `src/`.

### Data Layer (`assets/data/`)
JSON files that drive all content. Most are auto-generated by Python scripts via GitHub Actions (daily cron at 06:00 UTC):
- `profile.json` — Consolidated profile data (built by `build_profile_data.py`)
- `github_activity.json` — GitHub stats and repos
- `linkedin_profile.json`, `linkedin_recommendations.json` — LinkedIn data
- `projects_extended.json`, `tech_stack.json`, `blog_articles.json` — Content data

### i18n (`assets/i18n/`)
Translation dictionaries: `pt-BR.json`, `en-US.json`, `es-ES.json` (nested objects). Referenced in markup via `data-i18n-key` / `data-i18n-aria`. Build-time text is rendered by `src/lib/i18n.ts` (`t()`); runtime language switching by `assets/js/i18n.js`. **`public/assets` is a symlink to the repo-root `assets/`** — editing `assets/i18n/` updates both the build-time import and the runtime-fetched copy, so there is no duplicate to maintain. Keep keys in parity across the three files.

#### Traduzir a descrição de um repositório novo (seção `[09] Repositórios`)

`Projects.astro` renderiza os repos de `assets/data/github_activity.json` → `projects[]` (regenerado pelo `fetch_github_data.py` no CI diário) **em build-time (SSR, sem innerHTML)**. A descrição de cada card sai, por ordem de prioridade: (1) `projects.descriptions.<nome-do-repo>` no i18n → **traduzível** e troca de idioma via `data-i18n-key`; (2) fallback para a `description` do `github_activity.json` → **texto único do GitHub, sem tradução**. Quando um repo novo aparece, ele cai no fallback (2) até você adicionar a chave. Para traduzir:

1. Descubra o `name` exato do repo (case-sensitive) em `assets/data/github_activity.json` → `projects[].name` (é a chave usada: `projects.descriptions.<name>`).
2. Adicione `projects.descriptions.<name>` **nos três** `assets/i18n/*.json` (paridade obrigatória).
3. Rode `npm run build` — todo card cujo repo tem a chave passa a emitir `data-i18n-key` e a trocar de idioma; sem chave, degrada para a descrição do GitHub (comportamento OK).

Nenhuma mudança de componente é necessária — só as chaves i18n. Verifique a paridade das chaves de `descriptions` entre os três arquivos.

## Coding Conventions

- Astro components + scoped CSS; vanilla TypeScript in component `<script>` blocks; GSAP + Lenis for motion (no other JS libraries)
- 2-space indentation in `.astro`, CSS, and JS/TS
- kebab-case for CSS classes and data attributes (e.g., `hero-title`, `data-i18n-key`)
- Commit messages use Conventional Commits format (e.g., `feat:`, `fix:`, `chore:`)
- CSS custom properties live in `:root` in `src/styles/tokens.css` — never hardcode hex outside it

## CI/CD

- `.github/workflows/update-profile.yml` runs daily to fetch fresh GitHub/LinkedIn data, translate projects, build `profile.json`, and auto-commit to `assets/data/` and `assets/i18n/`.
- `.github/workflows/build-and-deploy.yml` builds the Astro site and deploys to GitHub Pages (`gh-pages`); the data-pipeline workflows dispatch it after committing `data:` changes.
- Additional data pipelines run on their own schedules (see the macro-cockpit, eleicoes, and worldcup workflow families).

## Sub-projeto: Observatório Eleições 2026

Painel apartidário sobre a *máquina de medição* da eleição (quem mede o
eleitorado, onde, com que rigor, a que custo) + o perfil real do eleitorado +
intenção de voto presidencial e estadual (medição, não previsão). Página
`src/pages/eleicoes-2026.astro` (16 seções). Dez JSONs em `assets/data/`,
todos consumidos por fetch em runtime (zero LLM):

```bash
pip install -r ingestion_eleicoes/requirements.txt
python ingestion_eleicoes/collect_pesquisas.py     # TSE Pesquisas 2026 → bronze
python transform_eleicoes/gold_eleicoes.py         # → eleicoes_pesquisas.json (métricas + concentração/custo)
python ingestion_eleicoes/collect_eleitorado.py    # TSE perfil eleitorado ATUAL (~2,3 GB, stream) → bronze
python transform_eleicoes/gold_eleitorado.py       # → eleicoes_eleitorado.json (perfil por sexo/idade/escolaridade/UF)
python ingestion_eleicoes/collect_precandidatos.py # Wikipedia PT (agrega pesquisas do TSE) → bronze
python transform_eleicoes/gold_precandidatos.py    # → eleicoes_precandidatos.json (1º/2º turno + panorama presidencial)
python ingestion_eleicoes/collect_estaduais.py     # Wikipedia PT, 1 artigo/UF (throttle anti-429) → bronze
python transform_eleicoes/gold_estaduais.py        # → eleicoes_estaduais.json (governador 1º/2º turno + senador, por UF)
python ingestion_eleicoes/collect_integridade.py   # roster do painel + TSE Dados Abertos (fail-soft) → bronze
python transform_eleicoes/gold_integridade.py      # → eleicoes_integridade.json (situação de registro por candidato)
python ingestion_eleicoes/collect_patrimonio.py    # TSE Dados Abertos, bens 2026+2022 (fail-soft) → bronze
python transform_eleicoes/gold_patrimonio.py       # → eleicoes_patrimonio.json (patrimônio declarado, 2022→2026 por CPF)
python ingestion_eleicoes/collect_prestacao_contas.py  # TSE Dados Abertos, receitas+despesas (fail-soft, sem dado real até 13/09/2026) → bronze
python transform_eleicoes/gold_prestacao_contas.py     # → eleicoes_prestacao_contas.json (arrecadação/gasto por candidato)
python transform_eleicoes/gold_fundo_ipca.py       # → eleicoes_fundo_ipca.json (deflator IPCA do Fundo: múltiplo real vs. nominal)
```

- `ingestion_eleicoes/catalog.py` — fonte única (URLs TSE + Wikipedia, mapa de colunas, normalização de candidatos/institutos, sufixos de UF, regras). Nunca hardcodar fora daqui.
- ⚠ **TSE exige fingerprint TLS de browser (Akamai Bot Manager).** Desde ~19/08/2026 todos os hosts do TSE (`cdn.`, `dadosabertos.`, `divulgacandcontas.`, e até `www.`) devolvem **HTTP 403** (`Access Denied … errors.edgesuite.net`) para `requests`/`curl` — **de qualquer IP** (residencial e datacenter, verificado) e independente de User-Agent. A discriminação é pelo **fingerprint TLS/JA3**, não por IP nem header. Solução em uso: `curl_cffi` com `impersonate="chrome"`, encapsulado em `tse_dados_abertos.http_get()` — **todo acesso a domínio do TSE deve passar por essa função**, nunca por `requests` direto. Diagnóstico que fecha a questão (22/08/2026, mesmo IP, mesma URL): `requests` → 403 · `curl_cffi(chrome)` → 200 (3 MB). Sintoma quando alguém esquece disso: pipeline "verde" com JSON congelado, só o `gerado_em` mudando a cada run.
- `ingestion_eleicoes/tse_dados_abertos.py` — helper compartilhado p/ TSE Dados Abertos (`dadosabertos.tse.jus.br`/`cdn.tse.jus.br`): baixa e faz parse dos ZIPs `consulta_cand_{ano}.zip` (registro), `bem_candidato_{ano}.zip` (patrimônio) e `prestacao_de_contas_eleitorais_candidatos_{ano}.zip` (receitas/despesas), latin-1/`;`-delimited, usado por `collect_integridade.py`, `collect_patrimonio.py` e `collect_prestacao_contas.py`. **O CDN do TSE recusa conexões de IPs de nuvem/datacenter com HTTP 403 de forma consistente** (mesmo bloqueio já conhecido da API DivulgaCand) — todo download é fail-soft (`baixar_zip_csv_brasil()` retorna `None` em vez de propagar erro) e detecção de coluna é defensiva (`checar_colunas()` só loga aviso; passar o dict de colunas esperado explicitamente via `colunas=` — inferir pelo texto do rótulo não funciona, todo nome de arquivo do TSE contém a substring "cand"). Colunas de `RECEITAS_COLUNAS`/`DESPESAS_COLUNAS` são o melhor palpite a partir do padrão TSE conhecido — **não confirmadas contra CSV real** (bloqueio de rede + dado só existe após 13/09/2026); ajustar no primeiro run real em CI se `checar_colunas()` acusar divergência.
- `assets/data/eleicoes_contexto.json` — **curado à mão** de fontes oficiais (cargos, Fundo Eleitoral, calendário, exterior, renovação). Cada bloco traz `fonte`/`fonte_url`. Atualizar quando o TSE publicar números novos (não é pipeline).
- **Fundo Eleitoral — múltiplo real (deflator IPCA):** `eleicoes_fundo_ipca.json` é gerado por `transform_eleicoes/gold_fundo_ipca.py` (companion do contexto, **não** o sobrescreve). Lê os valores curados do fundo em `eleicoes_contexto.json` (não hardcoda valores) e puxa o IPCA (BACEN SGS série 433, mesma série do Brasil Cockpit) via API REST — só `requests`. Deflaciona o FEFC de 2018 para reais do último mês publicado e emite o múltiplo REAL (~1,9×) ao lado do nominal (~2,9×) + `acima_inflacao_pct`. A seção [09] funde o companion no card e degrada para só-nominal se o JSON faltar. Fail-soft: se o BACEN cair, mantém o JSON existente.
- **Intenção de voto (presidencial + estadual):** fonte é a Wikipedia PT que agrega as pesquisas registradas no TSE (o dataset de registro do TSE não traz percentuais). Presidencial = 1 artigo; estadual = 1 artigo por UF (24 das 27 têm; faltam DF/MS/MT). Parsing de wikitables é frágil (2 formatos de partido, cargo pelo H2) → coletores fail-soft por estado/tabela, normalização no catálogo, throttle + retry anti-429 no coletor estadual, e passos de CI com `continue-on-error` (as seções degradam sozinhas). Governador renova em 1º/2º turno; Senado renova 2 de 3 vagas/UF em 2026. `gold_estaduais.py`/`gold_precandidatos.py` filtram por `ano == ANO_ELEICAO_PRESIDENCIAL` antes de montar o snapshot — sem esse filtro, uma UF cuja Wikipedia só publicou pesquisas de um ciclo anterior aparece com dado velho disfarçado de atual (achado real: BA/senador só tinha pesquisas de 2024). A nota de cobertura da §3 (`el-est-nota`, sem `data-i18n-key` — calculada em runtime) distingue UF sem artigo na fonte de UF com artigo mas sem pesquisa dentro da janela de recência.
- **Situação de registro (§13 "integridade"):** `eleicoes_integridade.json` (envelope: `metodologia`, `disclaimer`, `situacoes`, `fontes`, `itens_por_candidato`). Enquadramento neutro por **status de registro da candidatura** (deferido/sub judice/indeferido/cancelado/renúncia — não estágio de processo criminal). ⚠ Em ago/2026 o TSE publica `DS_SITUACAO_CANDIDATURA = '#NE'` (campo não preenchido) para **as 20.708 candidaturas**: o prazo fechou em 15/08 e o julgamento leva semanas. Por isso existe a situação `aguardando` ("Aguardando julgamento") mapeando `#NE`/`#NULO` — sem ela tudo caía em "Outra situação", que sugere anomalia onde só falta a decisão sair. Conforme os julgamentos ocorrerem, as situações reais aparecem sozinhas. O coletor lê o roster (presidenciais + governadores) dos JSONs do painel e casa por nome com `consulta_cand_{ano}.zip` do TSE Dados Abertos. Substituiu o desenho original (6 estágios via API DivulgaCand) porque essa API nunca teve código de eleição público para preencher e está no mesmo bloqueio de rede do CDN.
- **Patrimônio declarado (§14):** `eleicoes_patrimonio.json` — soma de `bem_candidato_{ano}.zip` por `SQ_CANDIDATO`, 2026 vs. 2022, casado por CPF mascarado do TSE (estável entre anos; nome/grafia não é). **Não cruza com Receita Federal** — sigilo fiscal impede qualquer API pública de patrimônio individual; o disclaimer do payload deixa isso explícito. Compara o próprio declarado do candidato entre os dois anos, não um valor "verdadeiro".
- **Prestação de contas (§15):** `eleicoes_prestacao_contas.json` — receitas + despesas por candidato do roster, join por `SQ_CANDIDATO`. **Já tem dado desde ago/2026** (o TSE republica relatórios financeiros durante a campanha; `PRESTACAO_PRAZO_PARCIAL`/`_FINAL` são só os prazos legais, não o início do dado) — os totais são cumulativos e sobem a cada coleta. Usa **`despesas_contratadas`**, não `despesas_pagas`: o arquivo de pagas (`despesas_pagas_*_BRASIL.csv`) não identifica o candidato, só traz `SQ_PRESTADOR_CONTAS`/`VR_PAGTO_DESPESA`. `renderPrestacao()` ainda tem o estado de contagem regressiva como fallback para quando o payload vier vazio.
- **Cruzamento doador × Receita Federal (§15):** o TSE publica `NM_DOADOR` (declarado pela campanha) ao lado de `NM_DOADOR_RFB` (nome que a Receita tem para aquele CPF/CNPJ) — colunas **confirmadas** no CSV real. Comparar os dois cru gera quase só falso positivo: no dado de 2026 foram **70 "divergências", das quais 66 eram acento/caixa/truncamento/abreviação** ("Maria Angela de Magalhães Junque" × "MARIA ANGELA DE MAGALHAES JUNQUE"; "JOSE M BORTOLI" × "JOSE MARIA BORTOLI"). `_nome_diverge()` em `collect_prestacao_contas.py` normaliza acento/caixa/pontuação, aceita prefixo (o TSE trunca `NM_DOADOR` em ~32 chars) e alinha tokens tolerando abreviação e partículas → sobraram 4 casos genuínos. **Nunca afrouxar isso sem re-testar**: num painel eleitoral, marcar acento como "divergência" insinua irregularidade inexistente. Doação de partido é excluída do check (nome do órgão ≠ razão social por construção). Não há equivalente para conferir patrimônio de pessoa física — sigilo fiscal.
- Cor: monocromático `--ink*` para dados + `--wc-gold*` para líder/destaque (sem cor partidária). Sem hex hardcoded.
- **Mapa de calor (§3 estaduais):** `buildGeoMap()` injeta `assets/img/maps/brazil-states.svg` (27 paths com `data-uf`) e pinta cada UF pela **margem do líder na corrida a governador (1º turno)** — intensidade em `--wc-gold-ink` (apartidário). Hover usa o tooltip flutuante global (`[data-tip]`) com líder/partido, intenção, margem s/ 2º, tendência e volume de pesquisas; clique sincroniza os painéis. `buildGeoMap` é reusável (`opts.selectable`, `opts.legendId`). O tile-cartograma `buildUfMap()` segue em uso na §5 (volume por UF).
- **Mapa presidencial por região (§2):** `eleicoes_presidencial_regioes.json` é **curado à mão** (não pipeline) de UMA pesquisa citável (Genial/Quaest jul/2026, registro TSE), verificada no texto. `renderPresRegioes()` reusa `buildGeoMap` (selectable:false) pintando cada UF pela margem do líder na SUA região. **Não há presidencial por-UF**: a intenção presidencial agregada (`precandidatos.json`) é só nacional e não existe fonte coletável/completa por estado (só ~10 estados em imagens; a Quaest agrupa Norte+CO → 4 macrorregiões). Bloco traz `instituto/registro_tse/fonte_url` + `disclaimer` de cobertura parcial; degrada oculto (`#el-reg[hidden]`) se o JSON faltar. Atualizar à mão quando sair rodada nova com recorte regional. Um monitor no CI — `transform_eleicoes/check_regioes_freshness.py` — **valida o schema** (regiões↔27 UFs completas, candidatos com %, metadados/fontes) e **avisa quando o dado está velho** (`data_ref` > 45 dias); nunca coleta/altera número (erro de schema → exit 1 vermelho; dado velho → ⚠ não-bloqueante).
- CI: `.github/workflows/eleicoes-pipeline.yml` (pesquisas + pré-candidatos + estaduais + integridade + patrimônio + prestação de contas, diário) + `eleicoes-eleitorado-monthly.yml` (eleitorado, mensal — job pesado).

## Sub-projeto: World Cup Dashboard (Copa 2026)

Painel **estático standalone** (não Astro) em `public/world-cup-dashboard/`
(`index.html` + `js/{main,deepstats,classics,motion,jumpnav,wc-match-combobox}.js`,
`css/style.css`). Servido direto no GitHub Pages via `public/`. Só o card teaser
`src/components/WorldCupCard.astro` vive no Astro. Sem i18n (pt-BR hardcoded).
Charts com **Chart.js 4.4.4** (CDN), não SVG hand-rolled. Cada `<section>` tem
mono-label `[ NN ]` sequencial em ordem de DOM; jumpnav auto-numera (inserir seção
= renumerar os mono-labels seguintes). Tokens `--wc-field*`/`--wc-gold*`/`--wc-live*`.

```bash
pip install -r ingestion_worldcup/requirements.txt   # só feedparser (resto stdlib)
python ingestion_worldcup/scraper.py                 # partidas/artilheiros/estatisticas/grupos/simulacao/… → data/*.json
python ingestion_worldcup/fetch_ball_level.py        # deepstats.json (momentum openfootball + stats de jogo inteiro ESPN)
python ingestion_worldcup/fetch_classics_statsbomb.py  # classics_2022.json (one-off — dado 2022 é estático)
```

- **Custo zero, sem API key.** JSONs vão para `public/world-cup-dashboard/data/`
  (NÃO `assets/data/`); runtime só faz fetch, zero LLM. Constantes/URLs inline nos
  scripts (não há `catalog.py`).
- **Limite de dado 2026:** ESPN só devolve **totais de jogo inteiro** (sem split
  1º/2º tempo, sem por-intervalo, sem PPDA/xG); openfootball só minuto de gol.
  As seções 04/05 mostram a ficha de jogo (28 stats ESPN em barras `wc-stat-row`;
  `fetch_ball_level.py` recomputa `pass_pct` de accurate/passes p/ precisão).
- **[07] Clássicos 2022 (`classics.js` + `classics_2022.json`):** reproduz FIEL o
  recorte das transmissões — **posse %, precisão de passe %, PPDA** por intervalo de
  15 min + Total/1º/2º tempo — com dado de **evento** aberto do StatsBomb
  (competition_id=43, season_id=106; CC BY-NC-SA). `fetch_classics_statsbomb.py`
  baixa 64 partidas (stdlib urllib) e calcula: posse = base temporal (tempo entre
  eventos por `possession_team`, clamp 30 s); precisão = passes completos ÷
  tentados; **PPDA = passes do adversário ÷ ações defensivas (desarme+interceptação+
  falta) na zona de 60% do campo longe do gol de quem pressiona**, com direção de
  ataque inferida do x médio dos chutes (frame fixo do StatsBomb). Não há evento
  aberto p/ 2026 → nunca fabricar intervalo/PPDA de 2026. **One-off** (dado 2022 é
  estático): rodar e commitar; não entra no cron diário.
- CI: `.github/workflows/update-world-cup.yml` (roda `scraper.py` +
  `fetch_ball_level.py`, commita `data:`, dispara build-and-deploy). O
  `fetch_classics_statsbomb.py` **não** está no workflow (dado imutável).
  ⛔ **Cron encerrado em 22/08/2026** — a Copa acabou em 19/07/2026, então não há
